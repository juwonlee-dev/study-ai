# CLAUDE.md

이 파일은 Claude Code가 이 저장소에서 작업할 때 따를 지침이다.

## 개요

- `study-ai`는 AI 도구 활용 스터디 과제 저장소다. 빌드·린트·테스트 도구는 없다.
- 최상위에 팀원별 폴더가 있고, 그 아래 `weekN` 주차별 산출물을 둔다.
- 이 폴더(`suhyeon`)가 사용자 본인의 작업 영역이다.

## 작업 범위

- `suhyeon/` 내부만 수정한다. 다른 팀원 폴더와 저장소 루트는 건드리지 않는다.
- 이전 주차 폴더의 파일은 참고만 하고, 사용자가 요청한 경우(리뷰 반영 등)가 아니면 수정·삭제하지 않는다.
- 과제에서 요구하지 않은 파일은 만들지 않는다.
- 파일 수정, commit, push는 사용자가 요청할 때만 한다.

## 과제 수행

- 새 과제는 최신 GitHub issue, 기존 PR 관련 작업은 그 PR 본문의 `Issue: #N`이 가리키는 issue를 기준으로 한다. 작업 전에 `gh issue view`로 요구사항을 확인한다.
- issue에 명시된 파일명과 경로를 그대로 따른다. 기본 위치는 `suhyeon/weekN/`이다.
- 마감 기한이나 충족하지 못한 요구사항을 발견하면 사용자에게 알린다.

## 작업 원칙

### 1. 작업 전에 생각하기
- 가정은 명시하고, 불확실하면 묻는다.
- 해석이 여러 가지면 임의로 고르지 않고 선택지를 제시한다.
- 더 단순한 방법이 있으면 먼저 말한다.
- 요청에 문제가 있어 보이면 그대로 따르지 말고 이유와 함께 말한다.

### 2. 단순함 우선
- 요청한 것만 만든다. 요청하지 않은 기능·추상화·설정은 넣지 않는다.
- 같은 결과를 더 짧게 낼 수 있으면 짧게 쓴다.

### 3. 필요한 부분만 수정
- 요청과 무관한 코드·문서·서식은 고치지 않는다.
- 기존 형식과 스타일을 따른다.
- 무관한 문제를 발견하면 고치지 말고 알린다.

### 4. 검증 가능한 목표로 실행
- 작업을 시작할 때 issue 요구사항을 체크리스트로 바꾼다.
- 여러 단계 작업은 단계마다 확인 방법을 붙인 계획을 먼저 제시한다.
- 끝나면 체크리스트와 대조하고, 충족하지 못한 항목을 그대로 보고한다.

## 분석·보고서 작성

- 모든 주장에는 근거를 붙인다. 코드라면 `파일경로:줄번호`를 적는다.
- 직접 확인한 사실과 추정을 구분하고, 확인하지 못한 것은 그렇게 쓴다.
- 등급이나 분류를 쓸 때는 그 기준을 보고서 안에 먼저 정의한다.
- 초안 작성 후 별도의 검토 단계를 거치고, 검토에서 바뀐 내용을 기록한다.

## 응답·작성 규칙

- 답변, 설명, 코드 주석, 출력 내용은 모두 한국어로 작성한다.

## 브랜치·PR

- 작업 브랜치는 `weekN/suhyeon`, PR base는 `main`이다.
- 커밋 메시지 예: `weekN/suhyeon: <작업 내용>`, `docs: ...`, `feat: ...`, `chore: ...`.
- PR 생성·리뷰는 `suhyeon/.claude/skills`의 `pr-create` / `pr-review` 스킬을 쓴다.
- Codex용 동일본은 `suhyeon/.codex/skills`에 있고, 두 SKILL.md는 같은 내용으로 유지한다.
- push·PR 생성 전에는 사용자 확인을 받는다.
