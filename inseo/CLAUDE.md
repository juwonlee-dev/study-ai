# CLAUDE.md
이 파일은 Claude Code가 study-ai 저장소에서 작업할 때 따를 지침이다.

## 개요
- study-ai는 AI 도구 활용 스터디 과제 저장소다.
- 최상위 팀원별 폴더 아래에 weekN/ 주차별 산출물을 둔다.
- inseo/가 사용자 본인의 작업 영역이다.

## 작업 범위
- inseo/ 내부만 수정하고 다른 팀원 폴더와 저장소 공통 설정은 건드리지 않는다.
- 이전 주차 파일은 참고만 하며 별도 요청 없이 수정하거나 삭제하지 않는다.
- 기존 변경 사항과 미추적 파일을 임의로 덮어쓰거나 삭제하지 않는다.
- 승인된 범위의 파일 생성·수정·검증은 직접 수행한다.
- 커밋·푸시·PR 생성·병합은 사용자 확인 없이 진행하지 않는다.

## 과제 수행
- 작업 전에 현재 경로, 브랜치, Git 상태와 최신 GitHub Issue를 확인한다.
- gh issue view 등으로 실제 요구사항과 제출 조건을 읽는다.
- Issue에 명시된 파일명, 경로, 마감, 검증 기준을 우선한다.
- 요구사항이 불명확하거나 도구 접근이 불가능하면 추측하지 않고 알린다.
- 과제에 요구되지 않은 파일, 기능, 의존성을 추가하지 않는다.

## 작업 원칙
### 1. 작업 전에 생각하기 (Think Before Coding)
- 목적, 입력, 제약, 성공 기준을 먼저 파악한다.
- 확인된 사실과 가정·추론을 명확히 구분한다.
- 해석이 여러 가지면 임의로 결정하지 않고 선택지를 제시한다.
- 요청의 문제점이나 더 단순한 방법이 있으면 근거와 함께 설명한다.
### 2. 단순함 우선 (Simplicity First)
- 요구사항을 만족하는 가장 단순한 구현을 선택한다.
- 불필요한 추상화, 설정, 예외 처리, 기능 확장을 피한다.
### 3. 필요한 부분만 수정 (Surgical Changes)
- 요청과 직접 관련된 파일과 코드만 변경한다.
- 기존 명명, 형식, 스타일을 유지한다.
- 무관한 문제를 발견하면 임의로 고치지 않고 별도로 보고한다.
- 변경 후 diff를 확인해 의도하지 않은 수정이 없는지 검증한다.
### 4. 검증 가능한 목표로 실행 (Goal-Driven Execution)
- 요구사항을 확인 가능한 체크리스트로 바꾼다.
- 여러 단계의 작업에는 단계별 검증 방법을 정한다.
- 가능한 검증은 직접 실행하고 실제 결과를 기록한다.
- 수행하지 않은 테스트나 미확인 결과를 성공으로 표현하지 않는다.

## 분석·보고서 작성
- 실제 코드, 설정, 실행 결과를 근거로 판단하고 대상 커밋 SHA를 기록한다.
- 코드 관련 주장은 가능한 한 파일경로:줄번호로 뒷받침한다.
- 보안 문제는 입력 경로, 발생 조건, 영향, 재현 근거, 조치 방안을 구분한다.
- 확인된 취약점, 잠재적 위험, 확인 불가 항목을 혼동하지 않는다.
- 위험도 등급의 판단 기준을 명시하고 등급별 건수와 상세 항목을 대조한다.
- 보고서 초안 이후 독립적인 2차 검토를 진행하고 변경·반박 근거를 기록한다.
- 외부 프로젝트 분석은 허가된 로컬 범위에서 수행하고 원격 공격은 하지 않는다.

## 응답·작성 규칙
- 답변, 설명, 보고서, 코드 주석은 한국어로 작성한다.
- 확인하지 않은 사실이나 실행 결과를 만들어내지 않는다.
- PR 본문과 리뷰 코멘트, 보고서에는 이모지를 사용하지 않는다.
- 완료 시 변경 파일, 검증 결과, 미완료 사항을 간결하게 보고한다.

## 브랜치·PR
- 작업 브랜치는 weekN/inseo, PR 대상은 Issue 지시가 없다면 main이다.
- PR 본문 첫 줄에 Issue: #번호를 기재하고 작업·검증 내용을 요약한다.
- 리뷰어 등 제출 조건은 해당 Issue에서 다시 확인한다.
